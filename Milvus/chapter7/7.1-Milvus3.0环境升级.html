Chapter 7.1 Milvus 3.0 环境升级 ​

7.1.0 这一章干什么 ​

这一章干一件事：把 Docker Compose 部署的 Milvus 2.6 升级到 3.0，升完之后想用新功能，知道去哪改配置。

写作基线：Milvus v3.0.2。

参考文档：使用 Docker Compose 升级 Milvus Standalone · Milvus 发布说明

7.1.1 升级步骤（Docker Compose） ​

先看官方验证记录：「升级过程中保留了 etcd、MinIO、Woodpecker 以及现有的数据目录，仅将 Milvus 镜像更换为 milvusdb/milvus:v3.0.2。」——保留的是官方验证环境里的依赖；你的部署有什么依赖就保留什么，唯一要动的只有 Milvus 镜像。

升级前准备：

  • 由 Docker Compose 管理的现有 Milvus 2.6.x Standalone 部署；
  • 用于现有部署的 Docker Compose 文件和配置；
  • Milvus 元数据和持久化数据的最新备份。

注意：「请勿在此过程中替换当前的 Compose 文件或更改依赖项版本。请保留现有的 etcd、对象存储、消息队列、卷和配置。仅更新 Milvus 镜像标签。」

步骤 1：备份当前配置。 保存当前 Compose 文件以及所有已挂载的 Milvus 配置文件的副本，然后确认当前容器状态正常（实际按你的文件名操作）：

bash
cp docker-compose.yml docker-compose-before-upgrade.yml

docker compose ps

3

元数据和持久化数据的备份是先决条件；官方安装文档推荐了 Milvus Backup——「一款用于 Milvus 数据备份的开源工具」。

步骤 2：更新 Milvus 镜像。 在现有 Compose 文件中，只把 standalone 服务的镜像改成目标版本：

yaml
services:
  standalone:
    image: milvusdb/milvus:v3.0.2

拉取目标镜像，并仅重新创建 Milvus 容器：

bash
docker compose pull standalone

docker compose up --detach standalone

官方说明：「Docker Compose 会保持现有的 etcd 和 object-storage 容器继续运行，并复用已配置的数据目录。」

步骤 3：验证升级。 先查容器状态、镜像版本和日志：

bash
docker compose ps

docker compose images standalone
1
2
3

验证 standalone 服务状态正常，且现有 Collections 仍可进行查询和搜索。在启用任何 v3.0.2 专属功能之前，请先完成这些检查。

注意事项：

  • 消息队列别换。 官方：「升级至 Milvus v3.0.2 时，必须保留当前的消息队列选择。升级过程中不支持在不同的消息队列系统之间切换。未来版本将支持更改消息队列系统。」
  • 别手动降级。 官方：「本操作流程不支持通过将 Milvus 镜像降级回 2.6.x 版本来执行降级或回滚。在 v3.0.2 写入数据后，仅回滚镜像的操作可能无法读取更新后的状态。如果升级失败，请停止写入操作，并使用恢复方案来还原升级前的元数据和持久化数据备份。请先在非生产环境中验证该恢复方案。」

参考文档：使用 Docker Compose 升级 Milvus Standalone

7.1.2 启用 Storage V3 ​

升级本身不会启用任何新功能。官方原文：「Storage V3 默认处于禁用状态。」后面的快照、TEXT 字段、外部 Collection都依赖Storage V3，用到时需要手动打开。

改什么配置：milvus-standalone 容器中的 /milvus/configs/user.yaml：

bash
docker exec -it milvus-standalone bash
cat << EOF > /milvus/configs/user.yaml
common:
  storage:
    useLoonFFI: true
EOF
exit
docker restart milvus-standalone

参考文档：使用 Docker Compose 运行 Milvus（Linux） · 存储 V3

7.1.3 本章小结 ​

  • 升级只做一件事：备份后，把 standalone 的镜像 tag 换成新版本，pull + up --detach，其余一律不动；
  • 两个注意事项：消息队列别换；升级失败走备份恢复，不要手动降级镜像；
  • Storage V3 默认关闭，用到快照/TEXT/外部 Collection 时在 user.yaml 打开 useLoonFFI 开关，开启后写入数据就回不去旧版。

环境就绪，下一章开始动真格：湖上一份 Parquet 文件，原地变成一个能查的 Collection。
